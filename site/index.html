The problem — 2026

ZK is powerful. The developer experience is not.

Existing prover marketplaces solve supply. Nobody has solved demand-side developer experience — the part where you actually ship something.

01

Choose a zkVM up front

SP1, RISC Zero, Jolt, Pico — each with different trade-offs, APIs, and proof formats. Pick wrong and you're locked in before you've shipped anything.

02

Build a prover pipeline

Custom prover infrastructure, or rent from a single marketplace. GPU clusters, recursion layers, proof-size budgets — a full-time job before you write product code.

03

Manage the compute yourself

Proving is compute-intensive. You need GPUs, autoscaling, and cost controls — or you pay a premium to a single provider with no leverage.

04

Start over if you switch

Need a different proof system or VM? There's no portability and no abstraction layer — you rebuild the pipeline from scratch.

Marketplaces like Brevis ProverNet and the Succinct Prover Network solve prover supply. They're "AWS for provers" — powerful, but you still architect the pipeline yourself. The demand-side layer is missing.

How it works

From source to verified proof

1

Push your code

Rust, C, C++, or anything that compiles to RISC-V or WASM. No ZK-specific code required.

zkvm.host deploy ./my_app.rs
2

The router picks a backend

Your workload is scored against SP1, RISC Zero, Jolt, and ZKWASM — the router selects for speed, compatibility, or WASM-native execution.

LLVM → SP1RISC-V → RISC ZeroWASM → ZKWASM
3

It's proven on decentralized supply

Your proof is generated on the best available prover — from ProverNet, Succinct, or our own fleet. You never manage the infrastructure.

4

You get an endpoint

A serverless API that anyone can call to verify your program's output — served via API, or posted on-chain.

GET /p/{hash}/verify → 200 OK

Why now — 2026

The timing lines up

RISC-V + STARKs is the standard

The abstraction layer is finally feasible — one interface can route to multiple backends without reinventing each one.

Prover marketplaces just launched

ProverNet (Dec '25) and the Succinct Prover Network (Aug '25) — the supply layer exists. The demand-side DX layer is still missing.

AI agents need verifiable execution

Every agent action should be provable. No one owns this niche yet — the first-mover advantage is substantial.

L2s are becoming application-specific

As settlement layers commoditize, application-specific zkVMs need a flexible hosting layer, not a single-chain tool.
